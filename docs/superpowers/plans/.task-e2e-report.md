## Final test:e2e tally
**82 passed / 2 failed** across 11 suites. The 2 failures are exactly the known pre-existing image tests in `runs.e2e-spec.ts`:
- "an image step persists assets, listed via /runs/:id/assets"
- "fans an image step out over a collection → one asset per item"

Both fail because the image provider (`ImageStepProvider`) needs the workspace **OpenAI** key (`/keys/openai`), but both tests set `/keys/image`. The run engine sees no OpenAI key, treats the step as locked, and breaks out leaving status `'idle'`. This is a pre-existing issue (unrelated to route migration) — the ImageStepProvider also makes a real HTTP call to OpenAI, so fixing the key without mocking the provider would cause an auth error in CI regardless.
