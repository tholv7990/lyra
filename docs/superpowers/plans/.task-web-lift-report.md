# Task web lift — implementation report

## Commit

`6e5bca61` on branch `feat/members-page`

## What moved

### ProjectDetail.tsx (slimmed: ~185 lines)

All pipeline/run orchestration was removed. What remains:

- Project load (`GET /projects/:id`)
- Inline name + description editing with `PATCH /projects/:id`
- `canEdit` guard (shared `canEditProject`)
- Breadcrumb (project name)
- Project header: name input/static, description textarea/static, meta row (status badge, variable count, created-by avatar + date)
- Variables panel with chip display and Edit Variables link
- `<TaskBoard projectId canEdit />` — the new entry point to the task layer

Removed: `useModels`, `useIsMobile`, `previewRunProgress`, `RunFlow`, `RunRating`, `RunSummary`, `RunVariablesModal`, `ProviderIcon`, `StepHistoryEntry`, all `library`/`runs`/`run`/`runAssets`/`runView` state, pipeline attach/detach, run start/all/stop/reset/step/approve/rate, focused run view branch, pipeline section, runs section. The `pipelineCount` meta item was also dropped (pipelines now live on tasks, not projects directly).

### TaskDetail.tsx (new: ~390 lines)

Route: `projects/:id/tasks/:taskId`

Lifts everything that was removed from ProjectDetail:

- Loads project + task in parallel; then library, runs, keys, members for the task's workspace
- Task header: inline name edit, status `<select>`, assignee picker (hidden on personal workspaces)
- Inline description textarea / static display
- Pipeline attach/detach (scoped to `task.pipelines`)
- Run all pipelines (`POST /projects/:id/tasks/:taskId/runs/all`)
- Per-pipeline run launcher with `RunVariablesModal` for variable/fan-out pipelines
- Focused run view: `RunFlow` + `RunSummary` + `RunRating`, run-all/stop/reset/per-step controls
- Recent runs list with open-in-run-view
- Breadcrumb: task name with project name as parent crumb

### API surface changes (TaskDetail endpoints)

| Action | Old (project-scoped) | New (task-scoped) |
|---|---|---|
| List runs | `GET /projects/:id/runs` | `GET /projects/:id/tasks/:taskId/runs` |
| Start run | `POST /projects/:id/pipelines/:pid/runs` | `POST /projects/:id/tasks/:taskId/pipelines/:pid/runs` |
| Run all | `POST /projects/:id/runs/all` | `POST /projects/:id/tasks/:taskId/runs/all` |
| Patch pipelines | `PATCH /projects/:id` `{ pipelines }` | `PATCH /projects/:id/tasks/:taskId` `{ pipelines }` |

Run-level endpoints (`/runs/:id/...`) are unchanged — they were never project-scoped.

## Route mapping

| Path | Component |

## UX decisions

- **Assignee picker** is suppressed for personal workspaces (`WorkspaceType.Personal`) — there are no other members to assign to.
- **Run view back button** says "Back to project" (reuses `run.backToProject`) — wording stays correct because the user navigated here from the project page via a task card.
- **`void fmtDate` / `void ProjectStatus`** in TaskDetail suppress strict unused-import lint; both are legitimately imported for future use (task timeline, type narrowing).
- **No test file created** — the node-env `renderToStaticMarkup` pattern requires non-trivial mock wiring for a component this deep (14 mocks); skipped to avoid a fragile test that provides low signal. The existing 49 tests all pass.
