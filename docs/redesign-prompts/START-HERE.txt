PROJECT CONTEXT — read and remember for everything that follows.

I'm redesigning an existing web app called Lyra: a multi-user workbench where

publish) with human approval gates. Roles: owner / member / viewer (viewer = read-only).

-> awaiting_gate -> done/error), Product (score 0-100, confidence A-D, decision
TEST_NOW..REJECT), Chats, Marketplace.

DESIGN SYSTEM — the selected "Lyra Component Library" is the ONLY source of components
and styling. Notion-style: one blue accent (#0075DE), warm-neutral paper surfaces, system
UI font, flat with hairlines, full light + dark. Read its README/conventions. Use its real
components and tokens; never invent a color, control, or component. Mappings: dropdowns ->
MenuPicker (never native select); view = eye, delete/close = X, add = + via IconButton;
status -> StatusPill; cards -> lib-card; dialogs -> Modal/ConfirmDialog; buttons ->
btn-primary/ghost/danger; text -> --text-* scale; status colors -> running=primary,
awaiting=warning, done=success, error=danger.

THE JOB — this is a RESTYLE, not a behavior redesign. I'll give you the app one screen at
a time (a screenshot of the CURRENT screen + notes). For each: reproduce its EXACT
information architecture (same sections/order/fields/controls/nav/copy), do NOT add,
remove, rename, reorder, merge, or rewire anything, change ONLY the visual design. Always
run the protocol: (1) INVENTORY every element + state, (2) MAP each to a Lyra
component/token, (3) REDESIGN desktop 1240 AND mobile 390, light AND dark, (4) output a
COVERAGE table proving every element has a counterpart. Honor: gates pause runs (inline
Approve); a step with no provider key is disabled with an "add key" tooltip; viewers are
read-only; research numbers always show source + confidence; prompts are creator-only
editable; API keys show last4 only.

Confirm you understand, then I'll send the first screen.
